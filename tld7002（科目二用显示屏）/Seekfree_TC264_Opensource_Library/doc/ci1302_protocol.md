# CI1302 语音芯片 串口通信协议对照表

## 一、帧格式

本协议包含两种帧：**握手帧**和**命令帧**，帧头不同。

### 校验算法（命令帧）

**CHK = 帧头到数据末尾所有字节之和的低 8 位**

```c
uint8 checksum = (sum of all bytes before CHK) & 0xFF;
```

---

### 1.1 握手协议（帧头 `A5 FA`）

CI1302 上电后发送握手帧，TC264 需回复握手应答后才能正常通信。

**CI1302 → TC264（握手发送）：**

```
| A5 | FA | 00 | 81 | 0D | 00 | 4A | FB |
| 帧头1| 帧头2| 固定 | 发送标志 | 数据 | 固定 | 校验 | 帧尾 |
```

固定帧：`A5 FA 00 81 0D 00 4A FB`

**TC264 → CI1302（握手应答）：**

```
| A5 | FA | 00 | 82 | 0D | 00 | 4A | FB |
| 帧头1| 帧头2| 固定 | 应答标志 | 数据 | 固定 | 校验 | 帧尾 |
```

固定帧：`A5 FA 00 82 0D 00 4A FB`

> TC264 收到握手发送帧后，需立即回复握手应答帧，CI1302 才会进入正常工作模式。

---

### 1.2 命令协议（帧头 `6B 79` / `6B 6A`）

语音识别结果和应答使用此格式。

**CI1302 → TC264（发送协议：语音识别结果）：**

```
| 6B | 79 | 00 | 81 | CMD_ID | 00 | CHK | FB |
| 帧头1| 帧头2| 固定 | 消息类型 | 命令词ID | 固定 | 校验 | 帧尾 |
```

- **帧头**: 固定 `6B 79`
- **消息类型**: `0x81` = 语音识别结果
- **CMD_ID**: 命令词 ID（1 字节）
- **CHK**: `(0x6B + 0x79 + 0x00 + 0x81 + CMD_ID + 0x00) & 0xFF`
- **帧尾**: 固定 `FB`

**TC264 → CI1302（接收协议：应答/播报控制）：**

```
| 6B | 6A | 00 | 82 | CMD_ID | 00 | CHK | FB |
| 帧头1| 帧头2| 固定 | 消息类型 | 命令词ID | 固定 | 校验 | 帧尾 |
```

- **帧头**: 固定 `6B 6A`
- **消息类型**: `0x82` = 应答
- **CHK**: `(0x6B + 0x6A + 0x00 + 0x82 + CMD_ID + 0x00) & 0xFF`
- **帧尾**: 固定 `FB`

### 1.3 帧类型区分方法

| 第1字节 | 帧类型 | 说明 |
|--------|--------|------|
| `0xA5` | 握手帧 | 后续为 `FA`，固定 8 字节 |
| `0x6B` | 命令帧 | 后续为 `79`(发送) 或 `6A`(接收) |

## 四、TC264 解析逻辑

```
收到串口数据流
  → 逐字节送入状态机
  → 检测到 6B 79 帧头
  → 读取后续 6 字节
  → 验证：byte[3] == 0x81 且 byte[7] == 0xFB
  → 验证校验：(byte[0]+...+byte[5]) & 0xFF == byte[6]
  → 提取 cmd_id = byte[4]
  → 根据 cmd_id 执行对应动作
```

## 六、注意事项

1. 上表 ID 编号从截图推断：**ID 1~3 为系统条目，ID 4~38 为 35 条命令**，请与 AI 平台逐条核对
2. CI1302 通信串口默认为 UART2，波特率 9600（以固件配置为准）
3. TC264 端需使用**独立串口**（如 UART1 或 UART2）连接 CI1302，不要与调试串口 UART0 冲突
4. 接线：CI1302 TX → TC264 RX，CI1302 RX → TC264 TX，GND 共地
